Use Python's set intersection: set(a) & set(b) gives you the words that appear in both. len(...) gives you the count. Loop over all docs, track the best score and the doc that produced it.

python
def find_relevant_docs(question, docs):
    query_words = set(question.lower().split())
    best_score = -1
    best_doc = docs[0]
    for doc in docs:
        doc_words = set(doc.lower().split())
        score = len(query_words & doc_words)
        if score > best_score:
            best_score = score
            best_doc = doc
    return best_doc

When Words Lie

★★☆☆☆ Easy

Observe

from acme_datasets import MINI_CORPUS
mini_corpus = MINI_CORPUS  # 8 sentences — includes 3 synonymous hotel-rate sentences

def keyword_search(query, corpus):
    query_words = set(query.lower().split())
    scores = []
    for doc in corpus:
        doc_words = set(doc.lower().split())
        overlap = len(query_words & doc_words)
        scores.append((overlap, doc))
    scores.sort(reverse=True)
    return scores

results = keyword_search("what is the hotel allowance", mini_corpus)
for score, doc in results:
    print(f"Score {score}: {doc[:70]}")

The first sentence scores highest (shares "hotel"). The second and third sentences mean exactly the same thing but score zero — they share no words with the query.

def semantic_search(query, corpus):
    query_vec = model.encode([query])[0]
    corpus_vecs = model.encode(corpus)
    scores = [(dot_product(query_vec, doc_vec), corpus[i])
              for i, doc_vec in enumerate(corpus_vecs)]
    scores.sort(reverse=True)
    return scores

results = semantic_search("what is the hotel allowance", mini_corpus)

    print(f"Score {score:.3f}: {doc[:70]}")

zip(vec_a, vec_b) gives you pairs like (a0, b0), (a1, b1), .... Multiply each pair and accumulate the total. Start with total = 0, loop with for x, y in zip(vec_a, vec_b), add x * y each iteration, return total.

python
def dot_product(vec_a, vec_b):
    return sum(x * y for x, y in zip(vec_a, vec_b))

The dot product between two normalized embedding vectors is equivalent to cosine similarity. Vectors representing semantically similar text will point in similar directions in the 384-dimensional space, producing a high dot product.

What you invented
Semantic search using vector embeddings — the retrieval backbone of every production RAG system. Instead of matching words, you match meaning. The dot product is a measure of how similar two pieces of text are in meaning-space.

python
def index_documents(docs):
    texts = [d["text"] for d in docs]
    embeddings = model.encode(texts)
    return list(zip(docs, embeddings))

def dot_product(a, b):
    return sum(x * y for x, y in zip(a, b))

def retrieve(query, index, top_k=2):
    query_vec = model.encode([query])[0]
    scored = [(dot_product(query_vec, emb), doc)
              for doc, emb in index]
    scored.sort(key=lambda x: x[0], reverse=True)
    return [(doc, score) for score, doc in scored[:top_k]]
What you invented
A vector index — the data structure at the heart of systems like Pinecone, Weaviate, and pgvector. Embed once, query many times.

Chunking and the Goldilocks Problem

★★★★☆ Hard
Chunking with overlap
The Problem

If you embed an entire 10-page PDF as one vector, you lose precision — the embedding averages over too many topics. But if you split every sentence, each chunk loses context. There is a Goldilocks size.

Load the long travel policy document and run the chunking function below.

python
from acme_datasets import LONG_TRAVEL_POLICY

def chunk_document(text, chunk_size=100, overlap=20):
    """
    Split text into chunks of ~chunk_size words,
    with overlap words repeated at the start of each new chunk.
    """
    words = text.split()
    chunks = []
    start = 0
    while start < len(words):
        end = start + chunk_size
        chunk = " ".join(words[start:end])
        chunks.append(chunk)
        start += chunk_size - overlap
    return chunks

chunks = chunk_document(LONG_TRAVEL_POLICY, chunk_size=60, overlap=15)
print(f"Created {len(chunks)} chunks")
for i, chunk in enumerate(chunks):
    print(f"\n--- Chunk {i+1} ---\n{chunk[:120]}...")

Experiment: Change chunk_size to 20 (very small) and then to 200 (very large). How does retrieval quality change? Write your observations as a comment in the code.

Very small chunks (20 words): High precision on simple factual lookups, but short chunks lose surrounding context. A chunk might have "is $250" with no mention of what the $250 applies to.

Very large chunks (200 words): Chunks cover multiple topics. The embedding averages over all of them, so a query about "alcohol" might retrieve a chunk that mentions alcohol in one sentence but is mostly about flights.

The overlap is important: without it, a relevant sentence that sits exactly at a chunk boundary gets split, and neither chunk captures it fully.

What you invented
Document chunking with overlap — a standard preprocessing step in all production RAG systems. The overlap prevents relevant sentences from being split across chunk boundaries and losing context.

import datetime

def get_current_date():
    return str(datetime.date.today())

def calculate(expression):
    allowed = set("0123456789+-*/()., ")
    if not all(c in allowed for c in expression):
        return "Error: invalid expression"
    try:
        return str(round(eval(expression), 4))
    except Exception as e:
        return f"Error: {e}"

def days_until(target_date_str):
    today = datetime.date.today()
    target = datetime.date.fromisoformat(target_date_str)
    return str((target - today).days)

Parsing and Executing Tool Calls

★★★☆☆ Intermediate
Tool dispatcher
Your Task

Complete the loop: parse the model's text output, run the right tool, and feed the result back.

python
def parse_response(text):
    """
    Returns:
      ("tool", tool_name, tool_input)  — model wants a tool
      ("answer", final_answer)         — model has an answer
      ("unknown", raw_text)            — parse failed
    """
    text = text.strip()
    lines = text.split("\n")
    if lines[0].startswith("TOOL:"):
        tool_name = lines[0].replace("TOOL:", "").strip()
        tool_input = lines[1].replace("INPUT:", "").strip() if len(lines) > 1 else ""
        return ("tool", tool_name, tool_input)
    elif lines[0].startswith("ANSWER:"):
        return ("answer", lines[0].replace("ANSWER:", "").strip())
    else:
        return ("unknown", text)

def run_tool(tool_name, tool_input):
    if tool_name == "get_current_date":
        return get_current_date()
    elif tool_name == "calculate":
        return calculate(tool_input)
    elif tool_name.startswith("days_until"):
        return days_until(tool_input)
    else:
        return f"Unknown tool: {tool_name}"

Now write one_step_agent(question) that asks the model, parses the response, runs the tool if needed, and returns the result.

def one_step_agent(question):
    raw = ask_with_tools(question)
    print(f"Model said: {raw}")
    result = parse_response(raw)

    if result[0] == "tool":
        _, tool_name, tool_input = result
        tool_result = run_tool(tool_name, tool_input)
        print(f"Tool result: {tool_result}")
        return f"Tool called. Result: {tool_result}"
    elif result[0] == "answer":
        return result[1]
    else:
        return f"Could not parse: {result[1]}"

Module 5 · Exercise 5.1

The Reasoning Loop

★★★★☆ Hard
Agentic loop · ReAct pattern
The Key Idea

An agent is not a single API call. It is a loop where:

  1. The model receives the question and any previous tool results.
  2. The model decides: do I have enough information to answer, or do I need a tool?
  3. If it needs a tool, run it, add the result to the conversation, go to step 1.
  4. If it has an answer, return it and stop.
Your Task

Build a multi-turn agent using a conversation history list.

python
def run_agent(question, max_steps=5):
    messages = [
        {"role": "user", "content": TOOL_PROMPT + "\n\nQuestion: " + question}
    ]

    for step in range(max_steps):
        print(f"\n--- Step {step + 1} ---")

        response = client.messages.create(
            model="claude-haiku-4-5-20251001",
            max_tokens=150,
            messages=messages
        )
        model_text = response.content[0].text.strip()
        print(f"Model: {model_text}")
        messages.append({"role": "assistant", "content": model_text})

        result = parse_response(model_text)

        if result[0] == "answer":
            print(f"\nFinal answer: {result[1]}")
            return result[1]

        elif result[0] == "tool":
            _, tool_name, tool_input = result
            tool_result = run_tool(tool_name, tool_input)
            print(f"Tool result: {tool_result}")
            messages.append({
                "role": "user",
                "content": f"Tool result: {tool_result}\n\nContinue. Provide ANSWER if done, or call another tool."
            })
        else:
            print(f"Parse failed: {result[1]}")
            break

    return "Agent exceeded maximum steps."

Add a simple external memory store with two new tools: remember(key=value) and recall(key).

python
memory_store = {}

def remember(key_value):
    """Input format: "key=value". Example: remember(monthly_budget=3000)"""
    if "=" not in key_value:
        return "Error: format must be key=value"
    key, value = key_value.split("=", 1)
    memory_store[key.strip()] = value.strip()
    return f"Remembered: {key.strip()} = {value.strip()}"

def recall(key):
    key = key.strip()
    if key in memory_store:
        return memory_store[key]
    return f"Nothing stored under '{key}'"
